# 0.9.0-alpha.1：离线验证与 Vic3 1.13 验收

## 云端可复现检查

Python 3.10+，仓库根目录运行，无第三方Python依赖：

```bash
python3 tools/generate.py --check
python3 -m unittest discover -s tests -v
python3 tools/validate.py
python3 tools/scenario.py
python3 tools/package.py
```

当前205项离线测试，其中32项为谈判与合同回归，22项为永久核算，26项为新增利益分配回归。测试读取实际生成的法案、效果、数值和本地化文件。`tests/native_runner.py`为这些脚本提供明确的原版数据夹具和受限效果执行器，不能代替游戏引擎。JSON往返检查脚本变量的持久性，不等于真实Vic3存档或随机数状态验证。

| 支持分 | 实际执行政治脚本，读取原版认可与政治力量夹具、领袖立场、实际权利法律、付费与违约分项；支持变化不改政治力量 |
| 合同对象 | 已拥有的实际州与签约基线；外国州区域取得后绑定实际州；拒绝用已有本国部分兑现新外国合同；其他州建设不兑现 |
| 履约追责 | 三年交付、五年未取得中性到期、失地复得与改法不刷新期限；兑现/违约只反馈相关集团，不叠加同名修正；迟建不撤销旧违约；取消新法案保留旧批准合同 |

部分离线模型仍含资源、同胞等设计输入，作为方案夹具，不代表原生代码已读取这些事实。新32项谈判测试执行实际政治与合同脚本；读取人口、建筑和集团时使用显式引擎数据夹具。为已退役的旧属性包改为验证其不存在及兼容清理；不以旧加成测试结果证明新方案。

## 社区符号与本体标识检查

```bash
python3 tools/validate.py --schema /path/to/cwtools-vic3-config
python3 tools/validate.py --game-dir '/path/to/Victoria 3/game'
```

社区CWT仅检查脚本符号覆盖，**不检查完整作用域、参数类型、列表枚举或1.13运行行为**。`--game-dir`只核对所需原版标识存在；不会启动游戏。当前云端没有1.13本体，数据库与游戏运行结果均为UNRUN。

## 必须完成的1.13游戏内验收

使用新测试档，启用调试日志，并只启用本模组；不要把旧alpha档当成已迁移存档。记录实际版本、国家、目标、选项、时间和日志，逐项确认：

1. 默认关闭，启用决议显示并能激活；国家领土原则、集团偏好和双语描述正常，其他语言显示英语回退。低合法性可讨论，破产/内战/主权资格符合流程。
2. 在不同国家提出相邻、区域利益、历史宣称与殖民目标；拒绝无实际资格目标，不依赖额外重点区域成熟。确保区域、相邻、领袖、殖民与权利法律标识在1.13有效。
3. 人类每90天看到谈判窗口及冻结州名；选择“继续”才结算该轮；关闭可重开。确认引擎窗口超时默认选项不会自动付费；AI继续，无人类弹窗。真实S/O、概率及八集团账目一致。
4. 签合同前后比对实际国库黄金与行政余额；确认`add_treasury`、`gold_reserves`和规划修正作用域，手续费只扣一次。破产、零人口、少储备、内陆海军基地、未研究铁路、条约港均不能错误签约。
5. 已有州记录实际建筑基线；其他州增加设施不算兑现，绑定州净新增一级才兑现。拆除后重建到原基线不算新增。确认1.13的`state_has_building_type_levels`是否按预期只读绑定州。
6. 外国合同取得目标区域普通州时绑定实际州，排除原已拥有部分和条约港；分割、转手、州对象销毁与复得均不可拿其他州刷兑现，期限不得刷新。对象销毁后的处理尤其需要本体确认，离线夹具不能证明重建后的州身份。
7. 三年到期未兑现使相关集团认可−5、信用−10五年；按时兑现认可+2三年。相同修正不叠加；真实到期消退。五年未取得释放规划预留，不追加建筑违约。
8. 葡萄牙拥有广东西部、另一国拥有同一区域其余部分时：逐实际州通过接纳、付款、满一年整合；不批准另一州。已付款项目不阻止另一个法案，但第二年度项目等待槽位。文化、宗教和接受等级继续原版变化。
9. 分别在谈判前、签约后、批准后、取得后、接纳项目中保存/读取真实游戏存档；冻结目标、勘察扣款、规划预留、期限与基线不变。旧事件不能操作新法案或新项目。
10. 原版主动战争、收复、防御和多目标战争仍运行；不额外扣厌战或用国内手续禁止战争。法案批准只是国内政治结果与宣称，不直接转移主权。确认旧效果没有残留在新档。

逐人口税额、自动融资、实际产权/利润/工资/组织成员、完整意识形态响应尚未实现；不用上述验收结果宣称它们已经可用。参数的方向、付出和退出条件见 [DESIGN.md](DESIGN.md)，数值属于待校准的游戏抽象。


## 0.8新增核算验收

离线22项核对三个开关独立与永久、模块关闭无影响、预算观察不重复扣款、全部五税档的升降与边界/30天冷却、各税制集团反馈和未知税制回退、0至100合法性连续征募公式、批准/扩张原则/实际战争/进攻领袖/参战缺项、条约港与外国州排除、同名征募修正替换与和平清理、三年到期存读、结束扩张保留合同、机构缺失/零使用量/行政缺口、服务投入恢复，以及所有语言每条自有文本恰有一个VTD前缀。

1.13必须另外核查：

1. 三项永久决议只在主系统启用后出现，对全存档各国生效，不改其他模块标记；保存读取后仍开启，AI不触发启用。
2. `net_total_income`、`total_expenses`、`bureaucracy_usage`的读取与游戏预算面板一致；是否含临时收入在账目中一致说明。开启与查看不产生新费用。
3. `set_tax_level`只真实升降一档，边界/破产/资金和30天冷却有效；原版收入延迟更新不能被误称作已计算未来收益。各税制名称在实际数据库存在。
4. `institution_investment_level:institution_schools`与医疗机构读取的是实际当前投入，而非目标扩建档；机构不存在安全记录0。行政压力百分比不得被界面标作覆盖率/效率。
5. 宣称通过后三年计划保持，未通过或和平不产生征募修正；`any_scope_war`的进攻领袖/参战关系正确，防御与非领袖无修正。此检查不是逐目标战争授权。
6. `state_conscription_rate_mult`通过可变倍率产生预期潜力值；合法性50为0，80为+6%，20为-6%，上下限相对±10%。确认与军事法律、最大征兵上限、其他修正的组合，以及既有部队是否受容量下降影响。
7. 多国、同一区域部分州、条约港、州转手和真实存读不会继承别国合法性修正；读档或同所有者检查保留有效修正，和平与计划到期在下一次月度刷新清除，主动结束计划立即清除。
8. 当前法案固定税/机构基线，税档增加与真实机构削减分别列入集团账目，刷新不叠加；恢复只消除对应反对。账目未知数据不生成虚构人口税额。
9. 所有VTD自有提示、修正标题、法律、日志和事件有一个前缀，英语回退一致；原版局部数值行通过VTD来源修正辨认，不覆盖所有原版词条。

社区符号检查并未验证上述作用域、1.13数值含义或真实游戏存档，当前实机均为UNRUN。


## 0.9分配合同验收

新增26项执行实际条款脚本，显式提供机构、市场、宗教和法律夹具；不模拟原版利润、改宗或政治成员。核对七类共享两槽、实际成本、教育冲突、机构存在/上限、低税与税制模块、地主法律快照、集团分歧、失效取消、追责、目标隔离、全国提前投入不能绕过精确州整合、年限与读档、旧窗口、迟交不重复获奖、失地复得不刷基线和机会事实。

1.13追加：

1. 五类新条款及原有两类占同一两个槽位；重复、负预算、无行政、条约港和原有部分不能扣错费用；未批准失效释放对应槽位但不退款，旧批准义务保留。
2. `institution:institution_schools.investment_max`和医疗机构上限，与实际当前投资级别的区别正确；已满或机构不存在不能签约。实际新增一级和精确绑定州正式整合同时满足才兑现。
3. `law_religious_schools`、`law_public_schools`、`law_serfdom`、`law_tenant_farmers`标识正确；国家宗教快照、宗教学校法律改变或土地制度切换按约追责，不把它显示为财产移转/人口改宗。
4. `religion_percent_state`以国家宗教为目标，49%/50%界限正确；不同市场/同一市场、市场接入49%/50%及主体主权正确。指标叫机会，不叫实得收益。
5. 外国区域取得后绑定实际普通州并保持签约机构基线；签约后可先进行全国投入，仍须绑定州正式整合。签约前已有本国部分、条约港和其他州整合不可冒充交付。
6. 低税/土地制度至少一年、两年验收；机构三年、主权五年等待；月度检查、存读、失地复得和改原则不延后截止。原版瞬时税档切换是否需要额外回调必须实测，现版本只承诺周期性观察。
7. 违约/兑现只影响相关受益集团，不叠加政治力量或人口奖励；日志标题分别对应审议、主权等待和绑定州。
8. 殖民与科技响应按八集团实际表分开，虔信者不再统一随科技改变；72个profile、中文/英语/九语言回退与VTD前缀一致。

游戏内项目效果、作用域、完整回调和真实存档均仍为UNRUN；社区CWT只验证符号。
