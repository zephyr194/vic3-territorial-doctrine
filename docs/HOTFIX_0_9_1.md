# 0.9.1-alpha.1：VTD运行问题修复

日期：2026-10-17。目标：Victoria 3 1.13.11。按用户七项需求及上传错误汇总修订，汇总内推断不作为已验证的引擎结论。

## 修改内容

1. **一次性状态**：状态决议打开当前国家的提示。点击“VTD 知悉”关闭并记录本国`td_status_acknowledged`，决议隐藏、读档保留。没有新增常驻系统日志。法案、整合、合同的进度日志仍按实际活动显示。
2. **逐州入口**：选州决议及菜单的内部操作移入`hidden_effect`，避免提示预览展开选州、变量赋值、刷新及后续事件。常规选州只刷新所有权记录，不再遍历所有人口；接受度诊断保留为独立操作。菜单保存`td_menu_target`，标题和操作绑定该窗口的州。旧窗口不能取消或推进另一州的新菜单，无候选或对象消失时显示无目标提示。
3. **法律显示**：移除法律组的运行中`enable`条件，固定显示在“法律 → 权力结构 → VTD 国家领土原则”。开始/载入初始化主系统，无现行原则时采用维持现状，已有原则不覆盖。
4. **本国过滤**：世界初始化留在启动回调，交互式状态入口不再初始化全球。状态只展示当前国家名称、人文研究阶段和本国殖民倾向参数，不列全球各州的潜在修正。确认按钮只写本国知悉状态，不发奖励。
5. **取消主开关**：采用用户的备选方案，移除“启用国家领土原则”决议，只保留一次性状态/知悉。旧调用效果仅兼容打开状态事件。财政、征募、服务三个独立永久核算模块仍按原有决议选择启用。
6. **事件配图**：全部可见事件引用模组自带的静态地图与议事厅插图。隐藏计时事件不配图；不依赖DLC或原版视频。
7. **日志报错**：修复`td_select_integration`、`td_refresh_integration`对`td_admitted_owner`的无保护读取，以及`je_td_admission_amendment`两项条件对`td_bill`的无保护读取。同时修复理由菜单及预算预览中尚未建立的`td_bill`/`td_pending_bill`读取、整合资格中的同类读取；旧接纳记录缺少理由时回退到民政理由。

## 安装

退出游戏后，解压本次源码包，运行其中`vtd.cmd update`更新已有安装；工具会备份旧载荷。首次安装用`vtd.cmd install`。Windows无需Python。使用0.9.1-alpha.1源码中的文件即可，更新前确认本地源码已包含本次修复。

也可解压`territorial_doctrine-0.9.1-alpha.1.zip`，将`territorial_doctrine/`与`territorial_doctrine.mod`放到用户文档的`Paradox Interactive/Victoria 3/mod/`。手动更新先完整备份并移出旧模组，再放入新版本，避免旧脚本残留。保留存档与其他模组，重启启动器并确认播放集只加载一份VTD。

载入时主系统会自动开启，包括此前未开启的存档；不会主动重置已有原则、已批准接纳、合同或年度项目。旧alpha完整迁移仍未完成，先用新测试档验收，已有存档用副本验证。

## 自定义配图

替换安装目录内`gfx/event_pictures/td_territorial_deliberation.dds`即可统一替换VTD事件图片，文件名与路径保持一致。随包图片为1536×1024、32位RGBA DDS，可用支持DDS的图像工具导出同格式。更新模组会覆盖本地贴图，请另存自己的原图。

不同事件也可新增DDS并修改`events/td_events.txt`中相应`event_image.texture`。核算事件由`tools/civic_assets.py`生成，开发时同时修改生成源。验证器会检查可见事件配图声明和贴图文件存在性。语法使用`event_image = { texture = "gfx/event_pictures/td_territorial_deliberation.dds" }`，参考社区[cwtools事件定义](https://github.com/cwtools/cwtools-vic3-config/blob/ba728e59a22e18dd590964e1c0201976852f46a8/config/events/events.cwt)，实际引擎显示仍需验收。

## 验证结果与边界

完整离线测试253项：241项通过，12项因当前Linux没有Windows批处理/PowerShell执行条件而跳过。新增11项覆盖无变量、首次选州、旧窗口、对象消失、知悉持久化与配图文件。测试夹具不再用虚构的`td_bill=0`掩盖未设置变量。脚本结构、本地化、生成一致性另行检查；离线执行器和JSON状态往返不等于游戏引擎或真实存档验收。

汇总中变量刷屏已在实际代码定位并修复。没有游戏本体、完整原始日志与可符号化堆栈；`C0000005`与脚本错误的因果尚未证实。本次针对无保护读取、复杂效果预览及无用人口遍历做了修复，**不能据离线结果宣称闪退已彻底解决**。

## 1.13.11实机验收

1. 仅加载本模组，用新测试档进入国家；无需启用决议即看到法律组与四项法律，无现行原则时维持现状。
2. 打开状态，核对当前国家；点击知悉后事件关闭、决议消失。保存重载仍消失；另一未确认国家可独立知悉。
3. 分别测试宣称、逐州接纳、批准州整合及无目标情况。检查首次打开、下一州、理由、取消与提交；旧窗口不能操作新州，标题仍指向原州。
4. 在没有法案、未接纳州较多的国家运行1—2个月，检查新`error.log`及`game.log`，确认没有`td_admitted_owner`、`td_bill`、`td_pending_bill`未设置及对应unset scope/invalid comparison连报。区分旧轮转日志，保留旧证据。
5. 检查状态、理由、审议、结果和核算事件均有配图，更换DDS后重启复查。
6. 用原问题存档副本重试同一国家与州。如仍闪退，保存当次原始`error.log`、`game.log`、`exception.txt`以及国家/决议/目标州名称，用于定位残余问题。
